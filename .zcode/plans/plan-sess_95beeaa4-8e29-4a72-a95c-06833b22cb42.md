## 资源包补齐方案：让「知识库 + 员工 + 应用 + 技能 + 扩展」成为可导入导出的场景包

### 设计原则（回应「灵活、模块化、不死板」）

1. **原语自治**：每个 primitive（knowledge / skills / agents / employees / apps / extensions）独立安装、独立降级——某一项失败只出 warning，不阻塞其他项（沿用现有冲突策略）。
2. **逻辑引用，不写死物理 id**：包内用逻辑名 `ref` + `${KB_REF:xxx}` 占位符把员工↔知识库连起来，安装时由安装器解析成真实 kb_id（复用现有 `${ORG_WORKSPACE}` 占位符模式）。知识库 id 是安装时生成的，员工 JSON 里写死 id 本来就不可能在包里表达——这是「组合使用」的关键接线。
3. **幂等**：知识库按 name get-or-create；文档 import upsert（content_hash 去重，unchanged 不重索引）；扩展 registry 行 upsert。重复安装安全。
4. **前向兼容**：未知原语/字段容忍（现状即如此），老平台装新包只 warning 不炸；不做 scripts/hooks 执行机制（安全边界，一切声明式）。

### 探索发现的阻塞 bug（必须先修）

`organizations/manifest.py` 缺 `import os`，但 `apply_placeholders()`（manifest.py:207）调用了 `os.getenv` → 任何带员工/应用的包安装都会 NameError 并整体回滚。**即当前团队/流水线类包安装实际是坏的**，修一行。

### 变更清单

**A. manifest.py**：补 `import os`；占位符体系在安装器层扩展 `${KB_REF:<ref>}`。

**B. 抽共享模块 `evoflow/admin/ui_extensions_registry.py`**：把 `app/gateway/routers/ui_extensions.py` 里的注册表逻辑（路径解析、BOM/单对象兼容读、原子写、id 校验、upsert/remove、`register_directory(path, link)` 高级入口）抽成 harness 内函数式模块；路由改薄封装（现有 15 个测试保证行为不回归）。安装器和导出器都复用它——之前"gateway 够不着 Tauri 注册表"的 Phase 1 前提已不成立（注册表就是共享文件）。

**C. installer.py：新增 knowledge 原语 + 接通 extensions**
- 安装顺序：workspace → **knowledge** → skills → agents → employees → apps → **extensions**（知识库必须在员工前，hire 时会校验 kb id 存在）。
- knowledge 条目：`{ref?, name, description?, import_folder?: "./data/reports", upsert?=true, prune_missing?=false, folder_prefix?=""}` → `list_bases()` 按名幂等 get-or-create → `owned_service.import_local_folder(...)`（记住 sync source，支持日后 resync；索引异步进行，返回值带计数）。artifacts 记 `knowledge: [kb_id]`，占位符表 `{ref: kb_id}`。
- extensions 条目三形态 + 向后兼容：
  - `{from: "./extensions/foo"}` 复制模式（包自包含，便携）→ copytree 到 `ui-extensions/<id>/` + upsert row；
  - `{path: <abs>, link: true}` 本机 folder-link（只登记，带非便携 warning）；
  - `{manifest: {...}, install_path}` 远程入口直登；
  - 老格式 `{id: "..."}` 仍只 warning（兼容旧导出包）。
- 员工/应用 payload 第二轮占位符替换 `${KB_REF:ref}` → 真实 kb_id（未匹配 → warning 保留原样，由 hire 的校验按冲突策略兜底）。
- uninstall：extensions 摘 row + 清理复制目录（仅限 ui-extensions 根下）；knowledge **默认保留**（数据安全），`options.delete_knowledge=true` 才 `delete_base`。
- preflight 的 will_install/warnings 同步更新（去掉两条 Phase 1 skip 警告）。

**D. export.py：导出补强**
- extensions：通过共享模块读 registry（现在 gateway 读得到了）——link 行导出 manifest + `{path, link:true}` 条目；copy 行整个目录 copytree 进包（>200MB 降级为仅 manifest + warning）。
- knowledge：include 新增 `knowledge_base_names` → 导出 base 定义；若 base 记住了 folder 同步源则 copytree 进包 `knowledge/<ref>/`（同样护栏），否则只建空库。v1 面板 UI 不动（CLI/手写 manifest 先行），面板勾选下轮再加。
- mcp/vaults 原语继续 Phase 1 skip（明确边界）。

**E. 测试**：manifest os 修复回归；registry 共享模块改造现有测试；installer 集成测试（tmp EVOFLOW_HOME + `EVOFLOW_OWNED_KB_WORKER=0`：小包含 skill+knowledge+extension(from)+员工 `${KB_REF}`，断言 kb 创建/员工绑定真实 id/扩展注册/幂等重装/uninstall 清理）；export 两形态扩展 + knowledge 导出；存量测试全绿。

**F. 文档**：resource-packs.md 补原语参考（extensions/knowledge + 占位符）+ 1004 示例；扩展文档 FAQ 加「也可打包进资源包」。

### 风险与边界
- `import_local_folder` 同步拷贝 + 异步索引：安装返回时索引可能未完成（返回计数 + 文档注明）。
- 大目录拷贝加 200MB 护栏；folder-link 明确标记非便携。
- 不做：mcp/vaults 原语、hooks 执行、面板导出知识库的勾选 UI、市场上架（后续轮次）。
